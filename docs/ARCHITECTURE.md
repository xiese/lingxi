# 架构说明

## 一、总体结构

系统采用分层设计，自下而上分为数据层、核心层、接口层与客户端层。

```
┌──────────────────────────────────────────────────────────┐
│  客户端                                                   │
│  Web 面板   kb-cli   MCP 客户端   第三方系统               │
└──────────────────────────────────────────────────────────┘
                          │
┌──────────────────────────────────────────────────────────┐
│  接口层                                                   │
│  Flask 蓝图（routes/）                                    │
│  routes_general  routes_notes   routes_search             │
│  routes_files    routes_llm     routes_admin              │
│  routes_auth     routes_integrations                      │
│  MCP 服务端（stdio / SSE）                                 │
└──────────────────────────────────────────────────────────┘
                          │
┌──────────────────────────────────────────────────────────┐
│  核心层（kb_lib/）                                        │
│  search   混合检索与索引    embed   向量化与精排           │
│  auth     鉴权与路径校验    store   令牌存储               │
│  config   配置与常量        audit   审计日志               │
│  llm      模型调用          graph   关系图谱               │
│  services/  领域服务（笔记、标签、索引状态、写入策略）      │
└──────────────────────────────────────────────────────────┘
                          │
┌──────────────────────────────────────────────────────────┐
│  数据层                                                   │
│  Markdown 笔记   索引文件   令牌与设置   审计数据库         │
└──────────────────────────────────────────────────────────┘
```

## 二、目录职责

| 路径 | 职责 |
|---|---|
| `scripts/kb_lib/config.py` | 常量、目录映射、设置的读取与保存 |
| `scripts/kb_lib/auth.py` | 令牌校验、路径安全校验、frontmatter 解析 |
| `scripts/kb_lib/store.py` | 令牌存储的读写与主令牌初始化 |
| `scripts/kb_lib/search.py` | 索引构建、增量刷新、BM25 与向量混合检索 |
| `scripts/kb_lib/embed.py` | 嵌入与精排的接口调用、分批与重试 |
| `scripts/kb_lib/llm.py` | LLM 对话调用与额度阶梯重试 |
| `scripts/kb_lib/audit.py` | 审计日志写入与查询 |
| `scripts/kb_lib/graph.py` | 笔记间关系图谱构建 |
| `scripts/kb_lib/routes/` | HTTP 路由，按功能域拆分 |
| `scripts/kb_lib/services/` | 跨路由复用的领域逻辑 |
| `scripts/web/` | Web 面板静态资源 |
| `scripts/kb-cli/` | 命令行客户端 |

## 三、检索实现

### 索引内容

索引包含三个产物，通过清单文件保持一致性：

| 产物 | 文件 | 说明 |
|---|---|---|
| 文本索引 | `.search_index.pkl` | 分词后的语料、BM25 模型、路径与内容 |
| 向量数据 | `.embeddings.npy` | 每篇笔记的向量表示 |
| 向量索引 | `.faiss.index` | FAISS 索引，用于近邻检索 |

清单文件 `.index_manifest.json` 记录三者的条目数，用于检测不一致。

### 检索流程

```
查询
  │
  ├─ BM25 关键词检索 ──┐
  │                     ├─ 倒数排名融合（RRF）─ 精排（可选）─ 结果
  └─ 向量检索 ─────────┘
```

1. **BM25 检索**：分词后计算相关性分数，取前 N 条。相关性判据是「是否命中查询词」，
   而非分数正负。
2. **向量检索**：将查询向量化，在 FAISS 索引中检索近邻。
3. **融合**：使用倒数排名融合（RRF）合并两路结果，`hybrid_alpha` 控制向量结果权重。
4. **精排**：可选。对融合后的候选做二次打分，未启用或不可用时直接使用融合结果。

### 降级策略

系统在设计上容忍外部服务不可用：

| 情形 | 行为 |
|---|---|
| 未配置嵌入服务 | 仅使用 BM25 检索 |
| 嵌入服务探测失败 | 跳过本次索引刷新，保持原索引不变 |
| 嵌入结果与笔记数不一致 | 禁用向量面，回退到 BM25 |
| 精排服务不可用 | 熔断 5 分钟，期间使用融合结果 |
| 精排单次超时 | 仅丢弃本次结果，不熔断 |

### 增量刷新

写入笔记后触发增量刷新，流程如下：

1. 对比文件修改时间，找出变更与删除的笔记
2. 若变更比例超过阈值，转为全量重建
3. 否则仅对变更部分重新分词并更新 BM25 模型
4. 混合模式下对新变更的笔记补充向量

刷新过程先快照当前状态，失败时回滚，避免出现「新文本 + 旧向量」的不一致状态。

## 四、数据模型

### 笔记

笔记为纯 Markdown 文件，元信息存于 YAML frontmatter：

```yaml
---
title: "标题"
type: knowledge
created: 2026-01-01
tags: [调研, 示例]
---
```

`type` 决定笔记所在目录，映射关系定义于 `config.py` 的 `TYPE_MAP`。

### 令牌

存储于 `$KB_ROOT/.api_tokens.json`，结构如下：

```json
{
  "master": {"token": "...", "created": "..."},
  "tokens": {"<token>": {"name": "...", "permission": "r", "expires_at": "..."}},
  "requests": {"<rid>": {"status": "pending", "device": "...", "ip": "..."}}
}
```

令牌以明文形式保存在该文件中，权限为 `600`（仅属主可读），并随 `$KB_ROOT` 一起纳入
`.gitignore`。设备令牌在签发时返回一次，之后服务端不再主动展示；`/auth/sessions` 只返回每个令牌的
`prefix`（前 12 个字符 + `...`）用于确认与吊销，不返回完整明文。

> **部署要求**：`$KB_ROOT` 所在目录必须只有服务账号可读。令牌文件等同于凭据，
> 不要放进版本控制、共享目录或备份到不受控位置。

## 五、安全设计

| 机制 | 说明 |
|---|---|
| 令牌分级 | 主令牌、只读令牌、读写令牌三级 |
| 路径校验 | 所有文件路径经规范化与目录穿越检查后才使用 |
| 受保护目录 | `70-经验` 等目录须显式携带 `owner_ack` 才能写入 |
| 设置脱敏 | 密钥类字段在读取接口中以 `<REDACTED>` 返回 |
| 审计日志 | 写操作、鉴权事件记录到 SQLite 审计库 |
| 分享扫描 | 导出前扫描敏感信息（密钥、本机绝对路径） |
| 默认监听 | 服务默认仅监听回环地址 |

## 六、并发模型

- HTTP 服务使用 waitress 多线程模型（默认 8 个工作线程）
- 索引对象由读写锁保护，检索读取与索引更新互斥
- 索引重建在后台线程执行，通过状态接口查询进度
- 嵌入与精排结果带缓存，减少重复的外部调用

## 七、扩展点

| 需求 | 扩展位置 |
|---|---|
| 新增接口 | 在 `scripts/kb_lib/routes/` 下新增路由文件并注册蓝图 |
| 新增笔记类型 | 在 `config.py` 的 `TYPE_MAP` 中增加映射 |
| 更换嵌入或精排服务 | 修改设置项，无需改代码 |
| 接入其他推送通道 | 参考 `push_qq.py` 的实现模式 |
| 新增 MCP 工具 | 在 `scripts/kb_mcp_server.py` 中以装饰器注册 |
