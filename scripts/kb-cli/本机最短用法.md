# 知识库本机最短用法（人用）

> 目标：本机上传/读写文档时，**不要**再走 `CLI → MCP → 上传` 大圈。

## 一句话

| 角色 | 路径 |
|---|---|
| **人在本机** | `kb-cli` / REST 直连 `8899` |
| **AI 客户端** | MCP（stdio / `8898/sse`） |
| **临时拖文件** | Web `/web/` |

**禁止：** 本机 CLI 再套一层 MCP 的 `kb_upload`。

## 为什么绕

`kb_upload` 读的是 **MCP 进程所在机器** 的本地路径，不是把你电脑文件自动传过去。  
远端 SSE MCP 上调用 `kb_upload("C:\\Users\\me\\a.md")` 几乎必失败。

正确本机链路：

```text
本机文件 → kb-cli upload / curl /upload → 8899 → 落盘
```

## 首次配置

```bash
# 拷贝 scripts/kb-cli/ 整个目录到本机任意位置（kb-cli.py + kb_cli/ 包）
python3 kb-cli.py config init
# 或
python3 kb-cli.py config set api_url http://192.0.2.1:8899
python3 kb-cli.py config set token <RW_TOKEN>

# 可选 alias
alias kb='python3 /path/to/kb-cli.py'
alias kb-up='/path/to/kb-up.sh'
```

环境变量优先级更高：

```bash
export KB_API=http://192.0.2.1:8899
export KB_TOKEN=***
```

本机若可直连服务器内网/本机服务，优先 `http://127.0.0.1:8899`。

## 日常 8 条命令

```bash
# 1) 上传现成文件（最短）
kb upload 笔记.md
kb upload a.md b.pdf -type knowledge
kb upload 笔记.md -dir 20-知识/工具研究
# 或
kb-up 笔记.md --dir 20-知识/工具研究

# 2) 创建结构化笔记
cat body.md | kb create -title "标题" -type knowledge -subdir "工具研究" -tags "调研,MCP"

# 3) 更新已有笔记
cat new.md | kb update "10-项目/知识库项目.md"

# 4) 搜索
kb search 关键词

# 5) 阅读
kb read "10-项目/知识库项目.md"

# 6) 列表
kb list -dir 20-知识 -limit 20

# 7) 重建索引（上传后搜不到时）
kb rebuild

# 8) 状态
kb status
kb health
```

## 场景对照

| 场景 | 用 | 不用 |
|---|---|---|
| 本机丢 md/pdf/图片 | `kb upload` | MCP `kb_upload` |
| 写一篇带标签笔记 | `kb create` | 无 |
| AI 对话里自动查/写 | MCP | 手写 curl 包一层 |
| 临时拖文件 | Web Upload | CLI/MCP |
| 批量 50 个文件 | `kb upload f1 f2 ...` 或脚本 | MCP |

## MCP 只给 AI

- Cursor / Claude / Hermes：接 MCP 工具（`kb_search` / `kb_create` / ...）
- AI 入库优先 `kb_create` / `kb_create_project_log`，不要靠本机路径 `kb_upload`
- 远端 SSE：`http://192.0.2.1:8898/sse`（适合搜写，不适合当本机网盘）
- **其他平台安装（Cursor/Claude/CodeBuddy/REST）**：`笔记/20-知识/工具研究/个人知识库其他平台安装指南.md`
