# 客户端使用方式对照

本文说明在不同场景下应选择的接入方式，避免链路绕远或误用接口。

## 一、按角色选择

| 使用方 | 推荐方式 | 地址 |
|---|---|---|
| 人工操作 | `kb-cli` 或 REST 接口直连 | `http://127.0.0.1:8899` |
| AI 客户端 | MCP（stdio 或 SSE） | stdio 脚本 / `http://127.0.0.1:8898/sse` |
| 临时上传文件 | Web 面板 | `http://127.0.0.1:8899/web/` |

## 二、关于文件上传的说明

MCP 的 `kb_upload` 工具读取的是 **MCP 服务进程所在机器** 的本地路径，并非将客户端
所在机器的文件自动传输过去。因此，从远程 SSE 连接调用 `kb_upload` 并传入客户端
本机路径（例如 `C:\Users\me\a.md`）无法成功。

上传本机文件的正确链路：

```text
本机文件 → kb-cli upload（或 REST POST /upload）→ 服务端落盘
```

即：人工上传走 `kb-cli` 或 REST 接口，不要经由 MCP 的 `kb_upload` 转发。

## 三、首次配置

```bash
# 交互式初始化
python3 kb-cli.py config init

# 或分别设置
python3 kb-cli.py config set api_url http://127.0.0.1:8899
python3 kb-cli.py config set token <令牌>

# 可选别名
alias kb='python3 /path/to/kb-cli.py'
```

环境变量优先级高于配置文件：

```bash
export KB_API=http://127.0.0.1:8899
export KB_TOKEN=<令牌>
```

## 四、常用操作

```bash
# 上传现成文件
kb upload 笔记.md
kb upload a.md b.pdf -type knowledge
kb upload 笔记.md -dir 20-知识/工具研究

# 创建结构化笔记（正文从标准输入传入）
cat body.md | kb create -title "标题" -type knowledge -subdir "工具研究" -tags "调研,示例"

# 更新已有笔记
cat new.md | kb update "10-项目/示例项目.md"

# 检索
kb search 关键词

# 阅读
kb read "10-项目/示例项目.md"

# 列出
kb list -dir 20-知识 -limit 20

# 重建索引（上传后检索不到时）
kb rebuild

# 状态与健康检查
kb status
kb health
```

完整命令参考见 [docs/CLI.md](../../docs/CLI.md)。

## 五、场景对照

| 场景 | 推荐方式 |
|---|---|
| 上传本机 md、pdf、图片 | `kb upload` 或 REST `/upload` |
| 创建带标签的结构化笔记 | `kb create` |
| AI 对话中自动检索与写入 | MCP 工具 |
| 临时拖拽文件 | Web 面板上传 |
| 批量上传多个文件 | `kb upload f1 f2 ...` 或脚本循环 |

## 六、MCP 的适用场景

- AI 客户端（支持 MCP 协议者）通过 MCP 工具访问知识库
- 内容入库优先使用 `kb_create` 与 `kb_create_project_log`，而非依赖本机路径的
  `kb_upload`
- 远程 SSE 方式适合检索与写入，不适合作为文件传输通道

详细说明见 [docs/MCP.md](../../docs/MCP.md)。

## 七、版本

- `kb-cli` 自 2.1.0 起提供 `upload` 与 `up` 命令
- 服务端版本以 `GET /api/version` 返回值为准
